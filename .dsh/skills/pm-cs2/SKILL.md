## 锁定比赛和子盘

调用 `sports_assistant` 时用 `{"action":"find","sport":"cs2","query":"战队和日期"}`，再以唯一的 `event_key` 调用 `inspect`。用户给了 Polymarket 链接时用 `{"action":"inspect","sport":"cs2","market":"用户给的链接"}`。字段名是 `sport`，参数校验失败时先修正参数。区分开赛计划和实际开打，核对两队、赛事阶段、BO 和地图顺序。对阵仍有歧义时给候选及当地时间。收到 `event_unverified` 时，按队伍、日期和赛事搜索原始记录，只使用查到或用户提供的比赛链接和原生 ID。

价格与成交必须绑定精确合约和选项。通过 `resolve_market` 核对 `localMarketId`、`conditionId` 和选项标签对应的 token，再用 `sports_assistant.inspect` 核对赛事与合约绑定。有多个子盘时按图序、阈值、选项或用户给定的链接选择。明确区分系列赛胜负、单图胜负、总图数、让图、单图回合数和回合让分。战队名和 Over/Under 按实际标签找 token，保留完整十进制字符串。

## 解说与复盘

用户问某个已保存回合时，用 `sports_assistant.inspect` 并同时传赛事实例及回合。已有 HLTV 比赛 ID 可用 `{"action":"inspect","sport":"cs2","event_key":"cs2:hltv:比赛ID","query":"图3 第5回合"}`，两队和日期都明确时也可用 `query` 查找。用 `facts.rounds` 的原始击杀顺序、覆盖、盘口和证据 ID 回答。指定过去可见状态时，将这条回合证据作为 `source_evidence_ids`。

先核对比分、地图状态和系列赛状态是否相符。BO3 任一方赢两图即结束。默认 MR12 的 13–11 是完图比分。不同来源冲突时，核对原生赛事、图序和观测时间，冲突未解就注明待核实。优先用已取得的 GOTV 事件、HLTV 战报或赛事方记录，随结论附原始链接、事件时间与可回查的证据 ID。

先讲改变回合的那一段交火。按原始顺序核对补枪、连杀前后的人数、下包或拆包、残局收尾。普通回合简短讲结果。反超、图点、加时和系列赛赛点要讲这一分如何改变下一回合，有已保存且连续的前一回合才引用追分或连胜背景。需要站位、经济或道具作为解释时，先核对原始记录。只有比分或零散事件时，说明能解释到哪一步。

结算问题以精确子盘条款和指定来源为准，区分实打回合、行政判图、规则推导和平台实际结算。无剧透请求用 `no_spoilers=true`，正文只给安全回放入口和覆盖信息，包括避开会泄露结果的走势、成交、比分和阵容变化。赛后用现有赛果复盘时照常 `inspect`。只有重建过去某一时点能够知道的赛事信息时才用 `mode=replay`，同时传带时区的 `as_of` 和当时已取得的 `source_evidence_ids`。缺当时快照时报告覆盖缺口，仍可按指定窗口查询公开成交。

## Polymarket 走势与成交

用户要盘面解读时，把场上转折和已核对子盘放到同一条时间线上。用 `query_sql(engine=clickhouse)` 按 `market_id = localMarketId` 和 `token_id = '<选项 token>'` 同时过滤。采用用户指定窗口或比赛、地图的已核对时间；分析单回合时取回合前后窗口，并写明实际时间范围。历史复盘严格截至指定时点。

- 走势用 `research_prices(start=...,end=...)` 查首末成交价格、时刻、高低和变化。需要细粒度走势时从 `research_trades` 分桶，或用 `read_polymarket_public` 的 `price_history` 查询同一 token，并注明采样间隔。用百分点表达变化，标明成交价、采样价或订单簿报价的口径。
- 默认逐回合播报与复盘摘要附一条代表性成交，优先当前图胜负盘最新一条带完整哈希的链上记录，再考虑系列赛胜负盘。保留原始时间、成交价、份数、完整交易哈希和可用的链上日志序号。用即时成交作样本且未取得哈希时标明待链上确认。用户要求全部或更多原始成交时，从保存的明细逐条返回，按需提供区块、入库时间、名义金额和 maker/taker。
- 历史成交用 `research_trades(start=...,end=...)`，取 `trade_time`、`price`、`size`、`fact_notional_usd`、`block_number`、`tx_hash`、`log_index`、`maker` 和 `taker`。源记录按日志逐条返回，即使同一 tx 有相同价量也保留。需要独立成交时，用覆盖合格的公开成交或已核对的撮合口径。公开成交用 `read_polymarket_public` 的 `trades` 按 condition 查，再按目标 token 和时间过滤。
- 比赛事件时间、来源观测时间、成交时间分开记录。只有观测或收包时间时标明时钟限制。首末价说明整个窗口的变化；要说价格在某一分钟、某个回合前后如何变化，须查该小窗口的成交。说明时间先后，因果解释需要额外证据。按实际响应附证据 ID，原样保留标识。窗口没有返回记录、查询失败和数据未采集分别报告，保留已经核对的比赛事实。

## 持续提醒

用户明确要求持续解说、逐回合播报或实时文字直播时，先用 Polymarket 官方数据核对赛事与系列赛胜负盘，再用同场 HLTV 链接核对实际地图顺序，调用 `cs2_live_commentary` 的 `start`，传 `event_slug`、`match_url` 与 `maps`。回执为 `streaming` 才确认直播，`lastMessageId` 才确认 Telegram 实际送达。报告来源或对阵无法确认的具体原因。PGL Singapore Major 使用官方 Kick 画面速报，`kickActive` 表示已有相符的画面回合入稿。CSTV 核对后更新同一条解说，缺少速报的回合由 CSTV 补录。每回合的盘口、价格变化和逐笔成交使用同场 Polymarket，以第一次观测到该回合结束为时间界限。选一笔代表性成交附完整交易哈希，并区分画面观测、CSTV 收包和成交时刻。

明确要求只提醒签到、开赛、地图状态、改期等比赛节点时用 `sports_assistant.watch_draft`。CS2 进度预设 `watch_preset: "cs2_commentary"` 自动填系列赛开打、每图开打和结束、系列赛结束，使用来源支持的最短周期。核实完赛后停止，最迟在计划开赛与订阅时刻中较晚者之后六小时结束。用户指定的条件、周期或到期时间覆盖相应默认值。

逐回合直播由 `cs2:live` 独立进程提供，与 Agent 使用同一 `PM_STATE_DIR` 才能查询同一份回合记录。传入已核对的 `--pm-event=事件slug` 时，采集已绑定的系列赛和地图胜负 token。显示采到的开打、结束收包时盘口和即时成交，以及可用的链上历史与时差。答复运行与送达状态时，以实际进程、任务或 Bot API 回执为准。
