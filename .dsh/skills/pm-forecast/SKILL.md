# 单市场赛果概率参考

- 问一场比赛的赔率、胜率、去水概率或融合，默认用 `forecast_market_odds`。例如「最近一场活塞比赛的赔率是多少？」也要输出书商赔率、官方五档、判断依据和融合概率。用户明确只要原始赔率与盘口时才用 `lookup_market_odds`。市场 ID 和选项从查询结果取值。
- 「只看两边报价」「只对照书商赔率和买卖五档」属于原始盘口查询。调用 `lookup_market_odds` 后使用它的 `reply`，到报价和时间说明为止。
- 只有球队或球员名时先定位赛事。没有指定盘口时用全场胜负盘。未指定日期或精确市场链接时，第一步用 `query_sql` 查开放的同场合约，再用赔率工具核对开赛时间。即使同一对手以前交手过，也按下一场回答。标题搜索返回的已关闭条目只能用于明确的历史查询。
- NBA 等以球队名为选项的全场胜负盘，先把球队翻成市场标签，例如活塞为 `Pistons`。用 `query_sql` 的 PostgreSQL 查询，下例把引号里的球队替换成实际标签。`polyv2-` 前缀的同时间同场条目是另一个合约候选，有标准赛事 slug 时优先用标准 slug。查询后的 `id` 加 `local:`，`outcome` 原样传给赔率工具。使用本轮查到的比赛，先据赔率工具的赛事信息确认开赛时间。
- NFL、NHL、NCAA、棒球和电竞也按这个方式查全场胜负盘，按联赛核对目标赛事。网球按球员姓名和赛事找整场胜负盘。问棒球比赛时先识别联赛和单场市场，赛季冠军盘有自己的结算对象。
- 板球、澳式足球、欧篮联及其他已接入的篮球和冰球联赛，按队伍、联赛和日期查整场盘口。Rugby 的 80 分钟胜平负可能拆成三个独立合约，先用 `event_title` 确认比赛，再选目标球队获胜或平局的合约。问「某队赢」时传该队获胜合约的 `Yes`。
- 问 90 分钟足球平局、板球 Test Match 平局时，从 `event_title` 定位同场，选平局合约，再按用户问的是平局还是不平局传 `Yes` 或 `No`。电竞比赛按项目和系列赛定位，用户明确说第几图时再查对应单图。

```sql
SELECT m.id, m.slug, m.title, m.end_date, o.outcome
FROM core.markets m JOIN research.outcomes o ON o.market_id = m.id
WHERE m.active AND NOT m.closed AND m.accepting_orders
  AND m.slug = m.event_slug AND m.end_date > :as_of
  AND lower(o.outcome) = lower('Pistons')
ORDER BY m.end_date, (m.slug LIKE 'polyv2-%'), m.id
LIMIT 5
```

如果给了双方队名，在上述查询补上对手条件 `AND m.event_title ILIKE '%对手的 Polymarket 队名%'`。例如板球 Dubai Capitals 对 Desert Vipers，查 `o.outcome` 为 `Dubai Capitals` 且 `event_title` 含 `Desert Vipers` 的开放胜负盘。这样可以直接拿到本轮要查的市场 ID。

- 结算、时效、去重与概率计算由程序处理。保留缺口，不用其他盘口代替，也不自行计算或补概率。
- NBA 全场球队盘、NFL 含加时全场胜负盘、足球 90 分钟赛果盘和电竞整场系列赛胜负盘，可使用已核验和按正常完赛口径假设的书商。程序逐家核对同盘口和时效，排除已知正常赛果冲突，并列出按假设纳入的书商。NFL 融合参考正常完赛且产生胜方。
- 用 `forecast_market_odds` 的 `mode=snapshot` 和 `snapshot_evidence_id` 按原时点复算。明确要求比较历史预测时用 `compare_odds_forecasts`。
- 解释缺口时以工具的 `diagnostic` 为准。开赛时间取赔率工具核对后的值，遇到改期优先使用已经核实的官方结构化开赛时间。目标开赛晚于有效快照里最远的开赛时间，才能说当前来源尚未覆盖到本场。发现同队近时赛事却未映射时，说明疑似队名漏配或具体开赛时间冲突。接口错误只说明读取失败，盘口空返回才说明无挂单。覆盖范围内没找到报价且无错配证据时说原因待查。当前快照缺失不能证明书商尚未开盘。

## 概率预测输出标准

1. **市场与选项**。一行标明比较的是哪场、哪个选项。
2. **书商赔率与来源**。每行只列书商、数据渠道和该盘口各选项的十进制赔率。展示最多四位小数。
   有公开历史报价时标注为历史参考，保留来源页面显示的记录时间，融合计算只使用合格的当前报价。
   电竞报价按工具返回的赛事依据完整展示。来源只写游戏项目或两边开赛时间有差异时，保留工具给出的说明。
   展示工具按需补到的公开书商报价，包括 CS2Odds 的系列赛赛前报价和 Sir Betalot 的页面参考报价，保留各选项赔率、来源和记录时间。某个来源没有报价时，仍展示其他来源和 Polymarket 已查到的数据。
3. **Polymarket 官方盘口**。买卖各显示最多五档，按最优价格起列价格和挂单份数。盘口版本较早时保留五档，带上工具已核实的官方读取时间和快照时间。
4. **Agent 判断**。有融合时，引用实际书商的赔率、去水分布及官方五档的价格和份数，说明双方是否同向和优势强弱。用合格书商的一致性、样本数，以及 PM 五档内双边各 100 份的可成交份数和均价差，解释哪边权重更高。注明估计未经校准。遇到缺口时，在受影响的数据栏给出本次能确认的原因和关键时间，仍然显示另一侧已取到的数据。
5. **三种融合结果**。程序用同一份合格输入并列展示 Bates–Granger 思路的动态权重、Ranjan–Gneiting 的等权线性池、Cont 等启发的盘口深度融合。第三种以同一份数逐档计算买入和卖出均价，用两者的中点替代最优报价中点，再与书商中位数等权融合。列出每种概率和权重。Beta 校准与 FFORMA 权重需要历史输入及赛果拟合，当前线性池按估计状态展示。
6. **默认胜率参考**。NBA 全场胜负盘以合格的 Polymarket 中间价作末行主参考。有书商对照时在上方列出三种融合数值和权重，缺少书商时仍给出 PM 参考并解释融合缺口。其他盘口在末行显示正常完赛条件融合概率，缺少合格输入时说明计算缺口。

程序拼接赔率、五档和融合值。判断段只解读 `judgment` 中的数据，不重复完整数字表，不补球队实力、伤病等未经查询的因素。默认不输出核验标准、采集状态、逐源有效期、公式、证据 ID 或回执。
